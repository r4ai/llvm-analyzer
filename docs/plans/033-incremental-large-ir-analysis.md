# 巨大IRのインクリメンタル解析

## Context

最新の `origin/main` では、PR #10によって意味解析の入力サイズに対して二次的に増える処理が解消されている。
約1.58 MiBの代表入力では、初回のスナップショット構築に約287.5 ms、1文字だけを変更した後の全体再構築に約319.0 msかかる。
さらに、language serverは同じopen documentを診断用とWorkspace Symbols用に二度解析しており、初回読み込みでも解析済み結果を共有していない。

初回読み込みでは解析済みスナップショットを全索引で共有し、通常の関数内編集では変更されたトップレベル要素だけを再パースする。
構造境界を安全に特定できない変更は全体解析へ戻し、解析結果の正しさを性能より優先する。

設計判断は [ADR 003](../adr/003-incremental-document-analysis.md) に記録する。

## スコープ

今回やること:

- `origin/main` で線形化された意味解析の契約と計算量を維持する。
- 前回のスナップショットから最小変更範囲を求める。
- 単一トップレベル要素内の編集では、その要素だけを再パースする。
- 境界をまたぐ編集と構造を安全に検証できない編集では全体パースへ戻す。
- language server、Workspace Symbols、Call Hierarchy が同じ解析済みスナップショットを共有する。
- 巨大IRの初回読み込みと単一命令更新を同じ条件で測るベンチマークを追加する。

今回やらないこと:

- LLVM verifier のインクリメンタル実行。
- 複数のトップレベル要素を同時に編集した場合の部分パース。
- 永続キャッシュやワーカースレッドへの解析分離。
- ASTの命令単位差分。

## 検証方法

- 変更前後のスナップショットが同じシンボル、診断、参照、CFGを返すことを単体テストで比較する。
- 同じ長さの局所編集では未変更のAST要素が再利用されることを確認する。
- トップレベル境界をまたぐ編集では全体パースへ戻り、正しい結果を返すことを確認する。
- `pnpm benchmark:large-ir` で初回読み込み、従来相当の全体更新、インクリメンタル更新を同じ入力で計測する。
- `pnpm test`、`pnpm test:coverage`、`pnpm typecheck`、`pnpm lint`、`pnpm format` を実行する。

## 実装結果

約1.58 MiBの代表入力で、1文字編集後のスナップショット更新は全体再構築の約284.4 msから約141.2 msへ短縮した。
単一トップレベル要素内の編集ではその要素だけを再パースし、意味モデルはモジュール全体を線形時間で再リンクする。

open documentの診断、Workspace Symbols、Call Hierarchyは同じスナップショットを共有する。
初回読み込みと索引登録を合わせた処理は、重複解析相当の約513.7 msから約263.7 msへ短縮した。

単一要素の内側に収まらない編集、要素が複数に分かれる編集、関数境界を壊す編集は全体パースへ戻る。
局所更新と全体解析のシンボル、診断、参照、CFG、全AST範囲の同値性をテストし、Vitestの行、分岐、関数、文カバレッジは100%を維持した。

本体とテストの複雑度は、TypeScript ASTを使った同一の規則で `origin/main` と作業ツリーを比較した。
対象は `packages/*/src/**/*.ts` と `scripts/*.mjs` であり、生成物と公開バレルを除外した。

| 対象   | 指標                         |  `origin/main` |         変更後 |
| ------ | ---------------------------- | -------------: | -------------: |
| 本体   | 循環的複雑度の最大値、合計値 |      51、1,209 |      51、1,273 |
| 本体   | 認知的複雑度の最大値、合計値 |        81、929 |        81、954 |
| 本体   | ファイル数、行数、関数数     | 30、8,452、459 | 31、8,846、499 |
| テスト | 循環的複雑度の最大値、合計値 |        11、555 |        11、572 |
| テスト | 認知的複雑度の最大値、合計値 |        28、102 |        28、102 |
| テスト | ファイル数、行数、関数数     | 16、4,883、473 | 18、5,077、490 |

最大複雑度は増えていない。
合計値とコード量は、AST全体の位置を型ごとに移す処理、全体解析へのフォールバック、性能ベンチマーク、同値性テストの追加によって増えた。
汎用オブジェクトを再帰的に書き換える短い案は、AST型で保証されないプロパティまで実行時に解釈するため採用しなかった。

この変更で追加したテスト義務は11件であり、未対応項目 `U` は0、義務総数 `O` は11、検証済み義務 `O_v` は11である。
論理ケース `T` は11、削除しても検出能力が変わらないケース `T_r` は0、独立シナリオの詰め込み `P`、理由のない層間重複 `D`、再試行依存 `F` はいずれも0とした。
新しいfixtureとtest doubleは追加していない。

`pnpm test`、`pnpm test:coverage`、`pnpm typecheck`、`pnpm lint`、`pnpm format`、`pnpm build`、`pnpm benchmark:large-ir -- --check` はすべて通過した。
VSCode 1.96.0のExtension Host E2Eも9件すべて通過した。
