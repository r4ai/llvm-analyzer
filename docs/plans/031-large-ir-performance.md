# プラン: 巨大LLVM IRの解析性能

## Context

language server は編集停止後にドキュメント全体を再解析する。
現状の `analyze` には、参照位置からソース末尾までの文字列コピーと、同一シンボルの既存参照を毎回走査する処理がある。

合成IRによる変更前計測では、3,200関数、約3.1 MBの入力に対する構文解析が292.7 ms、意味解析が3,662.7 msだった。
同じグローバルを参照する入力では、1,000参照の意味解析が7.5 ms、8,000参照では221.8 msとなり、入力件数に対して二次的に増加した。

## スコープ

- 多数の関数引数を調べるときに、ソース末尾までの部分文字列を作らない。
- 型定義の文脈判定を、参照位置より前のソース全体をコピーせずに行う。
- 同一シンボルの参照追加を、既存参照数に依存しない処理へ変更する。
- 位置問い合わせ用の識別子出現を一度だけ整列し、二分探索で検索する。
- 巨大IRを生成する再現可能なベンチマークを追加する。
- 外部契約、診断、シンボル、定義参照、型推定の結果を維持する。

## やらないこと

- parser をインクリメンタル方式へ変更しない。
- Web Workerや別プロセスへ解析を移さない。
- 巨大ファイルで一部の診断やLSP機能を無効化しない。
- ASTと意味モデルの公開APIを変更しない。

## 検証方法

- 多数関数と同一グローバル大量参照の2種類をベンチマークし、変更前後を同じ入力で比較する。
- 既存の analyzer テストで、関数引数、型位置、定義参照、位置問い合わせの契約を確認する。
- 巨大IRの公開契約を確認する結合テストを追加する。
- `pnpm test:coverage`、`pnpm typecheck`、`pnpm lint`、`pnpm format` を実行する。
- 本体とテストの認知的複雑度、循環的複雑度、行数、関数数を変更前後で比較する。
- 設計判断は[ADR 002](../adr/002-avoid-quadratic-full-document-analysis.md)と照合する。

## 探索後に追加した対象

Document Link用のファイル参照抽出も、全トークンをトップレベル要素ごとに再走査していた。
400関数で11.1 ms、1,600関数で162.3 msだったため、トークン列を一回の前方向走査で各要素へ対応づける処理もスコープへ追加する。

## 実装結果

多数関数の意味解析は、400関数で92.4 msから45.3 ms、1,600関数で847.2 msから159.0 msへ短縮した。
同一グローバル参照の意味解析は、1,000参照で7.5 msから5.4 ms、8,000参照で221.8 msから29.2 msへ短縮した。
Document Link用のファイル参照抽出は、400関数で11.1 msから1.7 ms、1,600関数で162.3 msから4.2 msへ短縮した。

`pnpm benchmark:large-ir -- --check` では、入力を4倍にしたときの正規化増加率が、多数関数0.9、同一グローバル大量参照1.1、ファイル参照抽出0.8だった。

TypeScript ASTによる同一測定では、本体の循環的複雑度は最大52のまま、合計1,306から1,329になった。
本体の認知的複雑度は最大90のまま、合計1,178から1,194になった。
テストの循環的複雑度は最大11のまま、合計577から581になった。
テストの認知的複雑度は最大28のまま、合計114から115になった。
ベンチマークと索引処理を追加したため、本体は8,440行、442関数から8,630行、458関数になり、テストは4,717行、485関数から4,744行、488関数になった。

`pnpm test:coverage` は281テストが通過し、statement 95.92%、branch 88.19%、function 99.2%、line 98.26%だった。
`pnpm typecheck`、`pnpm lint`、`pnpm format`、`pnpm benchmark:large-ir -- --check` も通過した。
