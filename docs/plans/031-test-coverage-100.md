# カバレッジ 100% のテスト補強

## Context

モノレポ全体のテストは実装ファイルの一部の行、分岐、関数、文を実行していない。

未到達箇所を数値だけで埋めると、実装の内部手順へ依存するテストや、複数の失敗理由を詰め込んだテストが増える。
そこで、公開契約、同値クラス、境界条件、状態遷移、失敗条件から独立したテスト義務を列挙し、各義務を最も狭いテスト層で一度だけ検証する。

## スコープ

### やること

- 現在の Vitest 設定を固定し、モノレポ全体の行、分岐、関数、文のカバレッジを変更前後で測定する。
- 未検証の公開契約、状態遷移、境界条件、失敗条件を特定する。
- 内部手順をモックせず、公開 API の入力と観測可能な結果を検証する最小のテストケースを追加する。
- 行、分岐、関数、文のカバレッジを 100% にする。
- テスト義務、論理ケース数、コード量、認知的複雑度、循環的複雑度を同じ条件で比較する。

### やらないこと

- カバレッジ対象の除外追加や閾値の緩和で数値を調整しない。
- 実装の内部呼び出し回数や処理順序を固定するテストを追加しない。
- 制御可能な内部依存をテストダブルへ置き換えない。
- 利用者向けの機能や公開 API の契約を変更しない。

## 検証方法

```sh
pnpm test:coverage
pnpm test
pnpm typecheck
pnpm lint
pnpm format
pnpm build
pnpm changeset status --since=origin/main
```

`pnpm test:coverage` の集計で Lines、Branches、Functions、Statements がすべて 100% であることを確認する。
変更したテストを一件ずつ外した場合に固有の義務が未検証へ戻ることを点検し、冗長な論理ケースを残さない。

## 実行結果

公開 API の入力と観測可能な解析結果を基準に、未検証だった 48 件のテスト義務を追加した。
論理テスト数は 284 件から 332 件となり、追加義務の未検証数は 0 件、重複義務は 0 件だった。
モック、再試行、複数義務の詰め込みは追加していない。

| 指標       |             変更前 |           変更後 |
| ---------- | -----------------: | ---------------: |
| Statements | 95.62% (1856/1941) | 100% (1842/1842) |
| Branches   | 87.51% (1171/1338) | 100% (1152/1152) |
| Functions  |   99.20% (375/378) |   100% (373/373) |
| Lines      | 98.20% (1640/1670) | 100% (1599/1599) |

カバレッジ除外は追加していない。
分母が減ったのは、配列境界や識別子種別など、到達不能な防御分岐を入力契約と型で表現し直したためである。
途中で閉じていない文字列、typed pointer 属性、配列の `extractvalue`、型を欠く関数シグネチャ、未知命令からの回復では、テストを先に失敗させてから観測可能な動作を修正した。

TypeScript AST を用い、`packages/*/src/**/*.ts` を同一条件で測定した。
行数は空行を除く物理行、循環的複雑度は判定演算子を含む経路数、認知的複雑度は制御構造の入れ子を加重した値である。

| 実装 KPI                    |    変更前 |    変更後 |
| --------------------------- | --------: | --------: |
| 物理行数                    |      7916 |      7840 |
| 関数数                      |       441 |       436 |
| 循環的複雑度（最大 / 合計） | 52 / 1304 | 51 / 1184 |
| 認知的複雑度（最大 / 合計） | 90 / 1079 |  89 / 982 |

| テスト KPI                  |   変更前 |   変更後 |
| --------------------------- | -------: | -------: |
| 物理行数                    |     3910 |     4329 |
| 関数数                      |      427 |      473 |
| 循環的複雑度（最大 / 合計） | 11 / 503 | 11 / 555 |
| 認知的複雑度（最大 / 合計） |  28 / 98 | 28 / 104 |

最終的に `pnpm test:coverage`、`pnpm typecheck`、`pnpm lint`、`pnpm format`、`pnpm build` を通過した。
さらに、sandbox 外で VS Code 1.96.0 を使った E2E 9 件を実行し、すべて通過した。
mutation test は既存の実行基盤がないため、今回の判定には用いていない。
