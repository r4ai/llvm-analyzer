# ADR 003: ドキュメント解析のインクリメンタル化

## Status

Accepted

## Date

2026-07-27

## Supersedes

なし

## Superseded by

なし

## Context

language server はドキュメントが変わるたびに、字句解析、構文解析、意味解析をファイル全体へ実行している。
この方式は実装が単純だが、巨大なLLVM IRでは1命令の編集でも初回読み込みと同じ待ち時間が発生する。

parserのASTはトップレベル要素ごとに独立した範囲を持つ。
一方、意味解析のモジュールスコープはトップレベル要素をまたぐため、局所編集でも参照解決の整合性を保つ必要がある。

## Decision Drivers

- 通常の関数内編集でファイル全体を再パースしない。
- 構造境界を誤認した解析結果を返さない。
- parserとanalyzerをVSCodeおよびLSPから独立させる。
- 初回読み込みと更新の両方を代表入力で再現可能に計測する。
- 既存のLSP機能と診断契約を維持する。

## Considered Options

### 1. 全体解析をワーカースレッドへ移す

全体解析を別スレッドで実行し、UIスレッドの停止だけを避ける。

得るもの:

- parserとanalyzerの変更を抑えられる。
- language serverのイベント処理を止めにくくなる。

失うもの:

- 編集ごとの計算量とメモリ転送量は減らない。
- 古い解析の中止とワーカー間の状態同期が増える。

### 2. 単一トップレベル要素を再パースし、意味モデルを再リンクする

前回のASTから編集を含むトップレベル要素を特定し、その要素だけを再パースする。
意味解析は線形時間へ直した上でモジュール全体を再リンクし、要素間参照の整合性を保つ。

得るもの:

- 通常の関数内編集で字句解析と構文解析の対象を局所化できる。
- モジュールスコープの定義追加、削除、重複診断を従来と同じ規則で処理できる。
- 境界を特定できない場合に全体パースへ安全に戻せる。

失うもの:

- 意味モデルの再リンクはファイル全体に対して線形時間で残る。
- 挿入と削除で位置が動く後続ASTは範囲の移動が必要になる。

### 3. 関数ごとの意味モデルを永続化する

定義、参照、診断、CFGを関数単位の断片として保持し、変更された断片だけを更新する。

得るもの:

- 関数内だけで完結する編集では意味解析も局所化できる。
- 巨大ファイルで更新時間を変更要素の大きさへ近づけられる。

失うもの:

- モジュール定義の変更が各断片へ与える影響を追跡する依存グラフが必要になる。
- 重複定義、未定義参照、rename、referencesの整合性を保つ可変索引が増える。
- 現在の不変な意味モデル契約を大きく変える。

## Decision

単一トップレベル要素を再パースし、意味モデルを線形時間で再リンクする方式を採用する。
通常の編集を局所化しながら、モジュールをまたぐ意味契約を一つの再リンク処理で維持できるためである。

変更範囲が単一要素に収まらない場合、要素の再パース結果が一つに定まらない場合、または前後のソース対応を検証できない場合は全体パースへ戻す。
性能のために不完全なASTを再利用することはしない。

## Consequences

良い影響:

- 関数内編集の字句解析と構文解析は変更された関数の大きさに比例する。
- 初回読み込みと意味モデル再リンクは入力サイズに対して線形に増える。
- 全体解析へのフォールバックにより、入力途中の壊れたIRでも従来のエラー回復を維持できる。

悪い影響:

- 意味モデル再リンクの線形コストは残る。
- 位置が変わる編集では後続ASTの範囲を移動する処理が必要になる。
- インクリメンタル経路と全体解析経路の同値性テストが必要になる。

中立的な影響:

- 意味解析の断片キャッシュは、再リンクが実測上の支配要因になった場合に別のADRで検討する。

## Scope

language serverが保持する開いているLLVM IRドキュメントへ適用する。
ワークスペース初期走査と外部LLVM verifierは全体入力を処理する。
