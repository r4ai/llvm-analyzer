# ADR 002: 全文解析からの二次時間除去

## Status

Accepted

## Date

2026-07-27

## Supersedes

なし

## Superseded by

なし

## Context

language server は、編集停止後にLLVM IRドキュメント全体をparserとanalyzerへ渡す。
この方式は解析結果を不変スナップショットとして扱える一方で、一回の解析時間が巨大IRの編集応答性を決める。

現状のanalyzerには、参照ごとに長い部分文字列を作る処理と、既存参照列を先頭から調べる処理がある。
そのため、入力中の関数数や同一シンボルの参照数が増えると、意味解析時間が二次的に増加する。

## Decision Drivers

- 診断とLSP機能を巨大IRでも省略しない。
- parserとanalyzerの純粋関数APIを維持する。
- 編集ごとの差分状態を新たに管理しない。
- 入力件数に対する二次時間の処理を、計測で確認した範囲から除く。

## Considered Options

### 1. 全文解析の二次時間経路を除く

参照位置の前後をindexで直接調べ、同じ出現の重複判定を定義範囲との定数時間比較に限定する。
位置問い合わせ用の出現列は解析完了時に一度整列し、二分探索する。
トップレベル要素とトークンの対応づけは、トークン列を一回だけ前方向へ走査する。

得るもの:

- 公開APIと解析結果を変えずに二次時間の経路を除ける。
- 追加する可変状態を解析中の配列だけに限定できる。

失うもの:

- 位置問い合わせのため、解析完了時に出現列を整列する時間がかかる。
- 出現列がソース順であるという内部不変条件を維持する必要がある。

### 2. 差分解析へ移行する

編集範囲に対応するトークン、AST、シンボルだけを再計算する。

得るもの:

- 小さな編集では、ドキュメント全体の大きさに依存しない応答時間を目指せる。

失うもの:

- エラー回復を含むparser状態と、関数やモジュールをまたぐ参照索引の無効化規則が増える。
- 差分状態と全文解析結果の同値性を検証するテストが必要になる。

### 3. 巨大ファイルで解析機能を制限する

ファイルサイズの閾値を設け、型推定や診断など一部の処理を省略する。

得るもの:

- 閾値を超えた入力の処理時間に上限を設けやすい。

失うもの:

- ファイルサイズによってLSPの外部契約が変わる。
- 閾値付近で利用者が受け取る機能が不連続に変化する。

## Decision

全文解析の二次時間経路を除く。
計測で確認した二次時間の原因を除き、公開API、診断、LSP機能を維持できるためである。

差分解析は、二次時間除去後の計測でも応答時間を満たせない場合に、別の判断として検討する。
機能制限は外部契約を入力サイズで変えるため採用しない。

## Consequences

良い影響:

- 多数関数と同一シンボル大量参照に対する意味解析時間の増加率が下がる。
- 巨大IRでも通常の診断とLSP機能を返す。

悪い影響:

- 解析完了時に識別子出現列を整列する処理が増える。
- 性能契約を継続して確認するベンチマークの保守が必要になる。

中立的な影響:

- 全文再解析と150 msのdebounceは維持する。
- 差分解析を将来導入する場合、この判断の計測結果を基準値として使う。

## Scope

parserとanalyzerから作る単一ドキュメントの不変スナップショットに適用する。
ワークスペース横断索引と外部LLVM verifierの実行方式には適用しない。

## Follow-up

- analyzerの走査と位置索引を変更する。
- 意味解析とファイル参照抽出の巨大IRベンチマークを追加する。
- 現在設計とロードマップへ反映する。
