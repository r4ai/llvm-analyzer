# ADR 004: 表示用型推論の要求時評価

## Status

Accepted

## Date

2026-07-27

## Supersedes

なし

## Superseded by

なし

## Context

language serverは、LLVM IRを開いた直後と編集後に、全SSA値の表示用型を推定している。
この型はhover、completion、inlay hintで使うが、診断、定義参照、semantic tokens、outlineの初期応答には不要である。

巨大IRでは、画面に表示されない関数を含む全命令の型推論が、初回読み込みと編集応答を遅らせる。
一方、型推論を要求ごとに繰り返すと、同じシンボルへの問い合わせが増えたときに計算量が増える。

## Decision Drivers

- 初回読み込みと編集後の必須解析から、表示専用の計算を外す。
- hover、completion、inlay hintが返す型を変えない。
- 一つの解析済みスナップショット内では、同じ型を一度だけ推定する。
- 表示範囲付きinlay hintでは、範囲外の型を推定しない。
- parserとanalyzerをVSCodeおよびLSPから独立させる。

## Considered Options

### 1. 全シンボルの型を解析時に推定する

意味モデル構築時に、従来どおり全SSA値の型を推定する。

得るもの:

- 型を使う最初の問い合わせに追加計算が発生しない。
- 意味シンボルを単純なデータオブジェクトとして保持できる。

失うもの:

- 型を表示しない利用者と画面外の関数にも同じ計算を行う。
- 初回読み込みと局所編集の待ち時間が、ファイル中の全命令数に依存する。

### 2. 型を問い合わせごとに再推定する

hover、completion、inlay hintを返すたびに元ソースから型を推定する。

得るもの:

- 初回の意味モデル構築から型推論を外せる。
- 意味モデルにキャッシュ状態を追加しなくてよい。

失うもの:

- 同じシンボルへの問い合わせで同じ計算を繰り返す。
- inlay hintの再要求回数に応じて計算量が増える。

### 3. 型を最初の参照時に推定して記憶する

意味シンボルは型推論関数を保持し、`type`が最初に読まれたときだけ評価する。
表示範囲付きinlay hintは、範囲で絞り込んだ後に`type`を読む。

得るもの:

- 初回読み込みと編集後の必須解析から、画面外を含む型推論を外せる。
- 同じ解析済みスナップショット内では、一つの型を一度だけ推定する。
- 公開する`SemanticSymbol.type`の読み取り契約を維持できる。

失うもの:

- 最初の型問い合わせに、そのシンボルの推論時間が加わる。
- 意味シンボル内部に評価済みかを表す小さな状態を持つ。

## Decision

型を最初の参照時に推定して記憶する。
初回読み込みと局所編集では表示に不要な計算を避け、型を使う問い合わせでは従来の値を維持できるためである。

inlay hintは要求範囲でシンボルを絞った後に型を読む。
これにより、エディタが可視範囲だけを要求した場合、ファイル全体の型推論へ戻らない。

## Consequences

良い影響:

- 初回読み込みと編集後のスナップショット構築時間が短くなる。
- 型推論の計算量は、ファイル全体のSSA値数ではなく実際に問い合わせたシンボル数に近づく。
- 既存のインクリメンタル構文解析と組み合わせ、局所編集後の必須処理を減らせる。

悪い影響:

- 最初のhoverまたはinlay hint要求で、対象シンボルの型推論を実行する。
- getterの一回評価契約を単体テストで維持する必要がある。

中立的な影響:

- モジュール全体の名前解決と診断は、整合性を保つため更新ごとに線形時間で実行する。
- 全ファイル範囲のinlay hintを要求した場合は、従来と同じ全SSA値の型推論が必要になる。

## Scope

analyzerが返すparameterとlocalの表示用型、およびlanguage serverの型表示機能に適用する。
構文解析、名前解決、診断、CFG、直接呼び出し抽出、外部LLVM verifierには適用しない。

## Follow-up

- analyzerの型保持を一回評価の遅延値へ変更する。
- inlay hintの範囲絞り込みを型参照より前へ移す。
- 巨大IRベンチマークに型問い合わせのシナリオを追加する。
- 現在設計とロードマップへ反映する。
